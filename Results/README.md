# Results

**This directory is not yet populated.** The manuscript's Data Availability
statement points readers here, so the analysis outputs must be committed before
submission.

Nothing in this directory is generated by GWASPoker itself. These are the
outputs of the four validation analyses, produced by the `Analysis5-*.py`
scripts, which are not currently in this repository either.

## What belongs here

| File | Produced by | Contents |
| --- | --- | --- |
| `Dataset1-DeclaredSSF.csv` | force-probe + GWASLab comparison | Per-study raw headers, field crosswalk, value-comparison counts for the 944 analysed records |
| `Dataset1-FieldSummary.csv` | same | Per-concept counts behind Supplementary Table S6 |
| `Dataset2-MetadataUncertain.csv` | paired GWASPoker/GWASLab recovery | Neutral raw-header screen, paired readiness and field recovery for the 263 paired files |
| `Dataset3-Benchmark50.csv` | controlled same-file benchmark | Per-file probe bytes, full bytes, timings and paired readiness decisions |
| `Dataset4-ExternalURLs.csv` | direct-URL probing | Per-URL outcome, failure class, recovered concepts and byte counts |
| `AllUniqueStudies.csv` | cohort construction | The frozen 2,208-accession source pool the benchmark drew from |

## Provenance to record alongside them

Each analysis should ship its GWASPoker `--provenance` JSON, which captures the
version, Python version, platform, GWAS Catalog data release, EFO version and
the fully resolved configuration. See
[docs/reproducibility.md](../docs/reproducibility.md).

## Version

The four datasets summarised in the top-level [README](../README.md#validation)
were produced by **GWASPoker 2.0.0**. Release 2.1.0 changed payload
classification, archive member selection and transport fallbacks — the paths
Dataset 4 measures — so re-running against 2.1.0 is outstanding. State in each
file, or in a sibling manifest, which version produced it.
